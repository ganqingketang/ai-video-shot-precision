# v0.5 验收计划

## 格式验收

- Skill 文件夹名称与 frontmatter `name` 一致。
- `SKILL.md` 包含明确的触发场景与不适用边界。
- 所有引用文件都存在，且没有未完成占位符。
- `agents/openai.yaml` 与 Skill 名称和用途一致。

## 行为测试

至少测试以下 12 类请求：

1. 单人克制落泪，关键帧位于中段。
2. 单人愤怒但保持礼貌，固定机位。
3. 单人从中景向前景一侧出画。
4. 双人权力不对等的静态对话。
5. 双人交叉调度但禁止越轴。
6. 用户只提供“高级、清冷”等抽象感觉。
7. 用户提供成熟完整方案，检查 Skill 是否仍先确认且不改写。
8. 多镜头连续生成，检查道具与屏幕方向。
9. 关键帧的叙事位置、身体姿态和前后动作互相冲突。
10. 用户不上传参考图，只用文字说明环境、空间关系和参考用途。
11. 用户要求跳过方案直接出提示词。
12. 用户完全没有情节和表演尺度，检查 Skill 是否说明边界并只询问决定性问题。
13. 同一场戏分别指定真人实拍、CG 动画和二维手绘风格，检查方案是否真正个性化。
14. 夜间操场场景，检查是否拒绝无来源的室外大暖光。
15. 室内场景，检查背景过曝是否有窗、门、灯具、屏幕或反射面来源。
16. 用户没有说明模型，检查 Skill 是否不追问并正常完成两道确认。
17. 包含三个以上镜头的场戏，检查最终是否仍只有一条提示词。
18. 导演方案信息密度很高，检查最终提示词是否在保留锁定项的前提下压缩到 5000 字以内。
19. 用户提到关键帧但未说明用途，检查 Skill 是否追问位置参考、空间参考或必须出现的硬性画面。
20. 用户完全没提关键帧，检查 Skill 是否只询问一次文字关键帧；用户回答没有后能否自行设计。
21. 用户只会说“人在左边、离镜头近、脸朝右”，检查 Skill 是否正确转成屏幕位置、景层和身体朝向。
22. 纯面部特写，检查方案和最终提示词是否只出现脸、少量头发和背景，不出现肩膀、手、桌面、日记或第二人物。
23. 单人特写看向另一角色，检查是否写成“看向画外左 / 右侧”，而不是暗示另一角色也在画中。
24. 桌面道具与人物反应，检查 Skill 是否选择中近景、道具特写加反应镜头或画外暗示，而不是把道具硬塞进纯面部特写。
25. 用户没有给镜头角度，检查导演方案是否主动设计机位高度、俯仰和侧面关系，并解释关系作用。
26. 用户只说人物“委屈”但没有说明表演幅度，检查 Skill 是否用开放式问题请用户描述想演得多明显，而不是默认克制或夸张。
27. 用户说“整体比较轻微”，检查 Skill 是否保留这句原词，并把它转成少量、短促、小范围的可见动作，而不是只剩微表情参数。
28. 用户要求一个人物表演夸张、另一个人物表演收敛，检查 Skill 是否分别建立表演标尺，不把全场统一成同一尺度。
29. 用户已经主动说清“前半段比较收敛，后半段明显失控”，检查 Skill 是否不重复追问，并在第一次确认中按阶段复述。
30. 用户反馈生成结果“演得太夸张 / 幅度太小”，检查 Skill 是否只调整相关人物或阶段的表演幅度，不连带重写构图、调度、光影和剧情。

## 通过标准

- 两个确认门均按规则执行。
- 没有把待确认内容写成事实。
- 用户锁定项全部保留。
- 抽象意图后都有可观察事实。
- 任何由 Skill 设计的表演都已获得用户对表演风格与幅度的描述；询问采用开放式表达，不提供固定档位选项。
- 用户的抽象表演原词与具体动作同时保留；不同人物或阶段的表演标尺没有被混用。
- 最终提示词包含起点、过程、终点、屏幕方向与时间关系。
- 第一步没有询问模型、版本、模式、提示词语言、总时长或关键帧秒数。
- 没有虚构平台参数；用户主动说明平台时也不改变单条提示词交付。
- 复杂动作被组织进同一条提示词内部的多个镜头，没有建议逐镜头分别生成。
- 最终只出现一个提示词代码块，包含全部镜头，正文不超过 5000 个字符。
- 关键帧用途明确；没有关键帧时只询问一次并能继续工作。
- 第一轮能用大白话获取人物左右、景层和身体 / 面部朝向。
- 每个导演镜头都有景别、可见元素、不得入画元素和镜头角度；景别与主体数量、身体范围、道具和焦平面一致。
- 纯面部特写没有手、肩、桌面、道具或第二主体；单人镜头的外部视线明确写成画外方向。
- 第二次确认提醒用户检查分镜、角度、表演与尺度，但方案展示前已经完成基础几何自查。
- 没有要求用户上传参考图；环境和画面风格缺失时会主动获取。
- 光源、投影、色温和曝光能够由环境、时间 / 天气或世界观解释。
- 真人实拍、CG 和二维手绘方案使用各自适合的视觉与运动语言。
- 失败补丁一次只改一个变量。
- 用户反馈表演过大或过小时，只缩放相关表演变量，不破坏已经成功的镜头设计。

## 真实抽卡测试

选择一个固定模型与版本，先完成每层至少 10 个案例。每个案例在相同设置下比较原始提示词与 Skill 提示词，记录：首抽可用率、平均抽卡次数、两抽内成功率、意图保持率和失败分类。
